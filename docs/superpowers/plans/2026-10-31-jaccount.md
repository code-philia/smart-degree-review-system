# jAccount Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add and deploy campus sign-in without disturbing local accounts or reports.

**Architecture:** Authorization-code + essential Profile API, browser-bound one-use states, then an existing application session.

**Tech Stack:** Express, Node crypto/fetch, SQLite, React, Vitest/Supertest.

**Spec:** docs/superpowers/specs/2026-10-31-jaccount-design.md

## Global Constraints

- Work in the existing rules-31-33-detectors server checkout; preserve untracked files.
- Secrets remain outside Git and frontend bundles.
- New identities start with STUDENT access; existing roles and data remain intact.
- English Conventional Commits. The user authorized pushing main and deployment.
- Do not modify the protected mutation-result CSV, call models or use OCR.

## Review Focus

- Invalid, missing, expired and replayed state must never authenticate.
- An upstream token/profile failure must not leak secrets or create a user session.
- Campus usernames matching a local administrator must not acquire that account.
- Concurrent/repeated campus authentication must preserve one identity and assigned roles.
- Password sign-in, report ownership and logout must still work after an additive schema update.
