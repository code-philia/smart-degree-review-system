# Numerical finding cards

The report reader must answer three questions in the fixed order **论点 → 论据 → 不一致处**. Each heading sits outside a clearly bounded content panel. The same production component serves historical and newly completed reports.

## Content

- Claim: use the saved assessment's explicit statement of the current claim. Otherwise select a complete source clause with an exact numeric token, preserving bounds, ranges, comparisons and bracketed context. A compound assessment can show a compact matrix only when existing declarations share the exact statement, metric and unit and form a unique, complete method/condition grid. It never supplies new values.
- Evidence: keep every evidence entry visible. Show the relevant cited fact and its applicability or attribution conditions from the saved analysis, or a focused, readable source table. Long PDF passages are not duplicated inside the card; each source retains a clearly labelled navigation button. Unreliable graph/table text uses the approved source-view message.
- Discrepancy: retain the stored status and assessment. Inconclusive results say 论据不足. An explicitly saved arithmetic comparison may show the original calculation and declared value; the UI performs no arithmetic and does not endorse or correct the calculation. The complete saved analysis remains available.

The renderer does not change finding counts, filters, report JSON, source anchors, detection, retrieval, prompts, models, OCR, email or API limits. No paper IDs, fixed values, page numbers or institution-specific conditions are embedded in product logic. Original source material retains its language; approved analysis translations use the existing translation machinery.

## Source navigation

The claim content and each evidence content region are clickable and keyboard accessible, using their exact existing source anchors. Keep the labelled source buttons alongside them. Numeric highlights use the same presentation content and selected-language analysis as the card, measured against PDF.js native text glyphs. Never replace an unresolved or ambiguous value with a paragraph-sized fill. Recycled text layers are measured again; translation updates refresh highlights without resetting the reader.

When the evidence card directs the reader to an unreadable figure or table, highlight its saved source region with a light tint and border, including when the figure has no native text. This exception applies only to those visual evidence entries; text evidence keeps precise value highlights.

## Design basis

Use short, decision-relevant facts and progressive disclosure for secondary analysis, following [NN/g](https://www.nngroup.com/articles/progressive-disclosure/) and [GOV.UK](https://design-system.service.gov.uk/components/details/). Evidence entries themselves remain visible as requested.

## Validation

Related frontend suites, production build, original-anchor interactions, language switching, narrow layouts and read-only replay of 100 saved reports cover this change. Existing baseline type errors are recorded separately; passing related checks is not a claim that the entire repository is green. Private report fixtures and preview assets remain outside Git.
