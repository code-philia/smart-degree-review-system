# Paper Model 与规则编译设计 v0.3

日期：2026-10-18（北京时间）。状态：**已按逐项问答修订，供审阅；新编译器、31—33 检测器、自动修复及 479 篇评测尚未实现或运行。**

## 1. 已确认目标与阶段边界

将论文视为具有结构、声明、引用和论证关系的程序。Paper Model 是类型系统、关系定义、构建能力和不变量；Paper IR 是某一篇论文的版本化实例。自然语言规则通过规则编译器变成读取 IR 的检测代码；论文变异在 IR 上发生。

本阶段的完整目标是：**先完成统一模型与 IR 设计，按新架构开发并上线第 31—33 条，完成 479 篇全量检测与结果交付；之后再替换已有规则。** 原先“本轮只交设计”的范围已被用户后续要求扩展，当前仍处于设计审阅阶段。

| 已确认事项 | 具体约束 |
| --- | --- |
| 自动化程度 | 自然语言规则输入后，解释、模型扩展、能力生成、代码生成、测试、反例归因、修复、验证均自动完成；运行闭环不依赖人工标注、复核或验收 |
| 规则入口 | 本阶段提供后台自然语言规则自动编译任务；网站新增 31—33 的选择、检测和结果展示，不新增面向用户的自然语言编译页面；国标是规则解释依据 |
| 自动扩展 | 超出现有算子的规则，要自动提出模型/能力扩展并验证；不能退化成开发者为每条规则手写检测器 |
| 标准优先 | 输入规则与适用国标冲突时按国标校正，保留原文、校正和条款；国标未覆盖但老师明确要求的规则仍影响最终检查结果，标为课题要求 |
| 标准版本 | 全部 479 篇统一使用所供 GB/T 7714—2025，不按归档年份切换版本；这是本课题的统一研究检查口径 |
| 数据范围 | 479 篇归档论文，229 专硕、160 博士、90 学硕；不承诺本阶段覆盖这批资料以外所有学科和格式 |
| 原始论文 | 不预设全部合规；变异前验证目标位置的前置条件，保留原有问题与新增问题的区别 |
| 测试来源 | 允许自动构造模拟论文 IR、环境证据和变异样例；合成测试与真实论文结论分开统计 |
| 首轮变异规模 | 每条规则至少 100 组有效原始/变异配对，来自至少 100 篇不同的归档论文；三条合计至少 300 组，不同规则可以复用母本；合成边界用例另计 |
| 不确定性 | 允许无法判定，但先自动重解析、扩展检索和交叉验证，尽量减少；优先减少误报 |
| R31 | 同时检查正文引用标记和文末参考文献著录格式 |
| R32 | 检查参考文献列出的外部文献是否真实存在，与 R22 的本地条目缺失分开 |
| R33 | 按引用位置的具体论述、方法或背景判断相关性；全文主题只辅助；摘要足以支持判断时可用摘要 |
| 上线与全量验收 | 新增 31—33；上线前必须真实执行 IR 变异检测、修复和回归，完成 479 × 3 = 1437 个原始论文—规则运行记录；已有 10 条后续再迁移 |
| 首轮结果与上线标准 | 第一轮原始结果先冻结并交付用户查看，再由用户决定上线标准；当前不预设零误报、零漏报或其他准确率门槛，不自动上线 |
| API | 密钥配置稍后处理。真实自动编译、语义判断和修复候选生成需要模型服务；未接入时只做设计、契约及离线测试，不声称语义闭环已验证 |

## 3. 设计选择

| 方案 | 能力与代价 | 结论 |
| --- | --- | --- |
| 给全文加章节 JSON 树，逐条编写检测器 | 初期容易，但引用绑定、外部身份、语义证据仍散落在各条规则中 | 不满足自动规模化目标 |
| 类型化 AST＋语义图＋能力注册表＋自动规则编译 | 保留结构与证据；通用能力可复用和自动扩展；需要独立验证编译及扩展候选 | 推荐，本文详细设计 |
| 将全文与规则直接交给大模型，返回问题列表 | 演示较快，但难以保证证据覆盖、隔离变异答案、控制自我修复 | 大模型作为受约束的抽取/判断组件使用 |

JATS 的 sec 和 xref 可作为章节及类型化引用的交换参考，但不能代替本项目的语义约束和演进系统：[sec](https://jats.nlm.nih.gov/publishing/tag-library/1.4/element/sec.html)、[xref](https://jats.nlm.nih.gov/publishing/tag-library/1.4/element/xref.html)。

## 4. 三种表示，各自负责一层

### 4.1 Layout IR：观测与定位

保存页、文字片段、字形/字体、阅读顺序、图像和公式区域、表格结构、OCR 结果、坐标变换。保留 PDF 物理页和印刷页码的区别，以及字符到页面位置的映射。R31 需要字符和排版依据，不能仅保留被大模型改写过的文字。

### 4.2 Document AST：正文的结构与对象

    Paper
    ├─ FrontMatter → Title / Abstract / ToC
    ├─ Body → Section → Heading / Paragraph / CitationGroup
    │                    ├─ Figure → Caption / FigurePanel
    │                    ├─ Table → Row → Cell
    │                    └─ Equation → MathExpression / SymbolMention
    └─ BackMatter → Bibliography → BibliographyEntry
                                  Appendix / Notes / ReadingList

每个结构节点有稳定 ID、原文内容、类型化属性、children 和来源。结构树单父；跨页内容有多个来源片段。章节的 method、results、review 是带证据的语义角色，不要求标题恰好叫“方法”，也不要求所有论文都有独立实验章。

缺图题、缺参考文献或悬空引用必须能表示为合法 IR；这些是论文可能存在的问题，不是装载 IR 时应删除或补造的字段。

### 4.3 Semantic Graph：链接、事实与论证

保存符号表、引用绑定、外部文献身份、引用用途、主张、方法、目标、结果、上下文以及 supports、answers、uses、contradicts 等类型化关系。关系均带证据、状态、产生者和版本；模型推断不是原文观测。

    CitationUse [1] → 本地 BibliographyEntry → 外部 ExternalWork
          │                                       │
          └─ CitationIntent / Claim ← 相关性证据 ──┘

R22 检查第一条链接；R32 检查外部资源身份；R33 检查该资源与本次使用的关系。R31 检查源标记及条目著录形式。同一条文献在不同位置使用时，R32 可以复用身份核验，R33 要逐引用用途检查。

数学表达式、表格数值、主张条件和跨章节证据作为通用模型扩展点保留；本阶段不实现其余 30 条的检测逻辑。

## 5. 自然语言怎样变成检测代码

1. **规则解释器（大模型）**读取原始规则、适用标准证据和模型契约，输出 RuleSpec：对象、范围、条件、例外、证据要求、判定表达式与来源。自动比较解释候选；无法消除歧义时报告编译未决原因，不等待人工补标签。
2. **类型与能力检查器**检查类型、字段、关系方向、证据义务和能力注册。缺字段/能力产生 CapabilityRequest，交给自动扩展流程，不由人工逐条补检测器。
3. **自动扩展器（大模型＋验证器）**生成候选 schema、迁移、抽取/分析能力代码、提示词及测试；在隔离环境验证类型、来源与回归。候选失败时继续有界修复，不能把未知能力替换成固定通过。
4. **确定性编译器**将已验证 RuleSpec 降为类型化 Rule IR，再由模板生成 Python 检查模块；解释执行器作为交叉验证后端。模型提出候选，编译器负责结构化代码生成。
5. **自动测试与发布器**执行正例、反例、等价变异、证据不足及服务异常用例，验证代码与解释器一致后生成带哈希的候选规则包。生产激活还需满足已配置的上线标准；本阶段先交付首轮结果，由用户决定该标准。

Rule IR 支持 select、forall、resolve、require_fields、validate_style、lookup_identity、judge_relevance、evidence_sufficient 等受约束操作。运行时只通过注册接口访问外部服务，检测模块不任意执行文件/网络/shell 操作。

这不是“永远只能组合固定算子”：能力不足时自动生成候选能力，验证成功后扩充注册表。也不是承诺任意自然语言都能立即正确编译；达不到证据或测试门槛时保留失败原因和旧稳定版本。

生成物至少包含原始规则与标准哈希、RuleSpec、Rule IR、代码、依赖能力版本、schema/model 版本、测试报告及发布清单。检测结果能追溯到具体规则包。

## 6. 运行与状态

论文前端先产生结构快照；依赖规划器按启用规则请求共享分析。外部文献元数据、摘要和全文经 Evidence Gateway 取回，作为有来源、时间、哈希和覆盖范围的证据加入分析快照。检测代码只读当前 IR 和匹配其哈希的分析。

结果使用 PASS、VIOLATION、UNKNOWN、NOT_APPLICABLE、ERROR。需要更多证据时进入内部自动核验队列；**不把“待人工复核”作为终态**。重复检索与模型复核达到预算上限后，仍不充分的结果为 UNKNOWN。

论文汇总输出违规数量、已完成对象数、证据覆盖、UNKNOWN/ERROR 原因和检查版本。存在违规时为 rejected；无违规但必需项未决时为 inconclusive；所有已选适用检查完成且无违规才为 passed。规则编译成功、IR 装载成功和论文检查通过分别记录。

R32 的检索无结果、404、限流、超时都不能独立证明文献不存在。R33 的全文主题不同、摘要未提到细节也不能独立证明引用不相关。检查优先减少误报，同时自动扩大证据以减少 UNKNOWN。

## 7. IR 变异与无人测试

正式变异编辑 IR 的原始内容或结构：修改引用标记、删除著录字段、替换被引资源身份或引用上下文。变异不直接写绑定结果、语义结论、诊断和评测答案；受影响分析必须重建。

变异事务保存父/子哈希、前置条件、操作、随机种子及失效依赖。合成内容标为 synthetic，保留祖先定位但不冒充原 PDF 中实际存在的内容。服务断网、检索无结果属于环境故障测试，与论文 IR 变异分开记录。

自动测试依据来自可计算约束、程序化构造与验证的样例、受控测试目录、可核实的正向外部事实、独立验证器和等价关系。大模型之间的一致意见只是信号，不能单独当作真实标签。

真实 PDF 解析使用独立抽取结果的一致性、来源片段/图像核对、可控 IR 渲染后再解析和结构不变量评估。没有人工真值时，这些是自动质量证据，不能据此宣称全部真实结构都已被证明正确。

479 篇默认未标注；真实全量报告和受控样例的 precision/recall 分开。所有原始论文可能有问题，变异应在目标前置条件成立后实施。同一论文及其变体保持同一数据划分，避免保留集泄漏。

第一轮每条规则至少覆盖 100 篇不同真实母本，每篇至少一组有效原始/变异对照，三条合计至少 300 组。可复用不同规则的母本，但同一篇的多个位置不能凑足该规则的 100 篇要求。合成论文、无效变异和无充分依据的预期不计入此数量；若真实有效母本不足，应如实报告缺口，不用合成数据补足。冻结首轮版本、样本、证据、原始诊断与统计后先交付；后续修复结果另存，不能覆盖首轮。

## 8. 自动修复与版本演进

闭环为：自动测试/运行一致性检查 → 收集带证据反例 → 定位解析、绑定、身份、语义、规则或 schema 层 → 生成候选 → 重建受影响 IR/分析 → 冻结回归和独立保留测试 → 影子运行 → 自动晋级或回滚。

候选不能修改原 PDF、标准、测试预期、评价逻辑或封存集。自动修改必须限于有版本的模型构建器、能力代码、提示词、编译规则或 schema/迁移。修改论文内容来消除违规不属于修复模型。

自动晋级策略必须检查来源/定位、测试与代码隔离、覆盖未被缩小、UNKNOWN/ERROR 未通过隐藏问题而改善、资源上限及目标修复效果。这些完整性要求不能替代尚未确定的准确率上线标准；当前只生成和评估候选，不激活生产版本。用户看过首轮结果并确定标准后，系统按版本化策略自动执行回归、晋级或拒绝。评价器与被修改检测器隔离；保留集只返回策略允许的汇总，不把具体失败内容交给候选生成器反复调参。

给每轮扩展设置候选数、迭代次数、调用成本、时间和失败停止条件。没有模型服务或预算不足时记录阻塞，不无限循环，不输出假通过。

## 9. 本阶段网站集成和验收

沿用网站的规则选择、异步任务、进度、报告及 PDF 定位入口；新增 31、32、33 三个规则项，接入统一 IR 运行服务。旧 10 条保持原有执行路径，后续以相同来源/诊断契约逐条迁移。

自然语言规则编译通过后台任务入口调用，保留任务状态、输入与编译产物供追溯；本阶段不开发网站上的自然语言规则输入与编译管理页面。

新规则显示问题位置、规范/课题依据、引用上下文、被引文献身份、核验证据链接、证据范围和自动核验轨迹。缓存按内容哈希、来源版本、检索时间策略、模型/提示词/规则版本隔离；重复文献可复用检索，但不同用途不复用 R33 结论。

**发布顺序是硬约束：** 先在隔离评测环境构建 479 篇原始 IR，建立目标局部的证据与变异前置条件；生成真实 IR 变体及另计的合成边界用例；冻结版本并执行首轮检测，交付原始结果供用户决定上线标准；按确定的标准进行自动修复与回归，再完成原始 479 篇全量及网站回归；满足标准后才上线。最终候选有变化时必须重新评测最终版本，并保留与首轮的对比，不能把首轮成绩冒充最终版本成绩。文档预期和少量演示不能替代真实变异检测。

验收同时包括：编译产物与测试；31 的正文及文末覆盖；32 的真实存在/身份冲突/不可核验区分；33 的方法跨学科合理引用与明确不相关反例；IR 变异与自动修复演示；旧规则回归；网站健康；479 篇、1437 个论文—规则记录以及按对象统计的证据覆盖。详细口径见阶段设计。

需要真实大模型服务后才能完成自然语言自动编译和语义实测。密钥稍后在服务器私有配置中接入；当前设计不读取或消耗密钥。待接口与预算确定后执行真实联调及全量任务。

## 10. 当前材料的可信边界

标准资料保留原文件和哈希，缺页/未核验条款有明确记录。R31 的每个可执行子检查在实现时必须关联已核对条款和适用条件，不能声称当前 17 份资料已全部编译。

当前 JSON 与代码形状是设计示例，预期结果保存在独立 oracle 文件；没有执行自然语言编译、真实外部核验或语义准确率评测。文档检查只能验证示例结构、哈希、链接和预期自洽。
