# 将论文视为可编译代码的规则自迭代框架

本设计取代 v0.4 中“本阶段不实现检测系统自修复”和“每条 100 篇不同母本”的安排。架构主线是把论文视为可编译的代码：PDF 解析为类似抽象语法树的 Paper IR，Paper Model 定义共享的结构与语义接口，自然语言规范编译成检查 IR 的程序，文献引用建立类似函数调用的绑定与语义关系。所有变异和检测都在 IR 及其分析上进行，已验证的误报漏报驱动系统自动修订模型、解析分析能力和检测程序。R31—R33 是同一论文编译框架的三个实验任务，30／300 条规则是后续快速扩展的目标。

## 1 已确认的范围

- 本轮只做 R31 引用格式、R32 文献存在性、R33 具体引用用途的相关性；暂不增加其他规则。
- 允许大模型自动修改检测代码，以及确有必要的 Paper Model、IR 解析与分析能力。
- 所有规则共用一套带版本的 Paper Model，每篇论文有自己的 IR，各条规则有自己的生成程序。模型明确包含标题、章节、Method、引用调用和参考文献条目等节点及其子节点，并提供符号与语义关系；复用已有结构与来源映射，按需要扩展，不为每条规则复制模型。Method 节点由来源支持的解析或分析产生，不是仅在文档里声明一个名称；不要求每篇论文都存在独立的方法章。
- 检测器与变异器统一操作 Paper IR；原始 PDF 作为解析输入和来源定位依据保持不变。新规则以自然语言及规范材料输入编译框架，不能靠开发者按规则编号增加手写检测分支或变异配方来扩展。
- 每条 100 个有效违规 mutant，共 300 个；允许同一母本产生多个不同变体。合规和等价对照另计，不能抵充违规 mutant。
- 每条的 100 个是总样本量，约 60 个用于反馈、20 个用于验证、20 个用于独立测试；不是额外要求 100 个留出测试样本。同一母本的变体归入同一集合。
- 每条最多 5 轮生成与评估：初始程序为第 0 轮，最多 4 次修订。生成或修订失败也占一轮，不能通过嵌套重试绕过上限。提前收敛可停止，未收敛也保留实际成绩及剩余错误。

## 3 方法与新流程

将框架收敛为四个研究模块：论文建模与解析、规则编译、IR 变异与反馈、模型与程序协同修订。它们构成论文编译器的主线，不把缓存、部署、队列等工程设施作为方法贡献。

| 模块 | 输入 | 输出 | 核心作用 |
| --- | --- | --- | --- |
| 论文建模与解析 | PDF 的原文、版面和来源证据；当前 Paper Model | 结构树、符号绑定、语义关系及分析 | 提供共享、可定位、可变异的 Paper IR |
| 规则编译 | 自然语言规则、标准条款、IR 接口、已有共享能力 | 可执行检查程序与必要的模型/分析扩展 | 通过大模型合成论文编译检查 pass |
| 变异反馈 | 自动构造并复核的原始/变异 IR、密封预期、当前程序预测 | 误报、漏报及其他失败案例 | 将可核验差异转成具体反例 |
| 程序与模型修订 | 原规则、当前版本、失败证据、历史反馈 | 新程序及有依据的模型补丁 | 自动归因、修订、重新构建与回归 |

### Paper Model、结构树与语义关系

Paper Model 定义论文的节点种类、属性、父子关系、符号、引用及语义关系接口。解析和分析程序负责把实际内容转成这些信息；自然语言规则编译出的检测程序是使用这些接口的检查 pass。Paper IR 是某篇论文的具体实例，包含结构树、符号表、跨节点关系及来源证据，不是一个平面的文本或参考文献字段集合。

下面是概念示例，实际节点保留稳定 ID、类型、属性、子节点及原文位置；跨节点箭头表示引用关系，不改变树的父子约束。

```text
Paper
├── Title
├── Abstract
├── Body
│   ├── Introduction
│   ├── Method
│   │   ├── Paragraph
│   │   │   └── CitationCall ──绑定──> ref_12
│   │   └── Equation
│   └── Results
└── References
    └── ReferenceEntry(symbol=ref_12) ──身份核验──> ExternalWork
```

当前 Section、Heading、Paragraph、CitationGroup、ReferenceUse、BibliographyEntry 及已有分析可作为基础。CitationCall 是引用调用的概念接口，可在保留兼容映射的前提下由 ReferenceUse／CitationGroup 表达；Method 必须有明确的语义类型和来源支持，可对应来源章节，也可作为关联原文片段的派生语义节点。语义节点若跨多个结构片段，通过关系和来源映射连接，不伪造原文层级或产生多父结构树。Argument、Hypothesis 等后续能力仍按规则需求扩展。

### 引用作为函数调用的编译视角

| 编译概念 | 论文中的对应物 | 本轮检查 |
| --- | --- | --- |
| AST 与语法检查 | 标题、章节、正文引用标记及文献条目 | R31 检查适用格式与规范 |
| 符号引用与外部依赖解析 | 引用位置绑定本地条目，再识别外部真实作品 | R32 核验外部作品存在性；区别于仅检查本地引用绑定 |
| 调用语境与语义约束 | 具体引用用途，以及被引文献可提供的支持、方法、定义、比较或批评依据 | R33 检查该用途是否有依据，不退化成题名或领域相似度 |

这是一种组织表示和检查的编译类比，不把文献语义冒充成已经形式化证明的函数签名。外部检索失败、全文缺失或无法判断引用用途时，保留 UNKNOWN，不能直接认定调用非法。只有在选定规范范围内，覆盖完整且适用检查全部通过，才可报告论文编译检查成功；发现违规输出带位置及依据的诊断，信息不足和执行错误分别输出。

### 所有变异与检测均以 IR 为工作对象

变异针对 IR 中的来源节点、文本、属性或合法关系，维护语法结构、来源记录和依赖失效；随后重新进行受影响分析。不能直接把计算出的相关性、存在性或规则结果改成预期值，冒充有效 mutant。模型修订后从同一来源和同一冻结变异重建 IR，不修改原 PDF 或样本答案。

检测 pass 读取 IR 及其分析，通过统一接口获得外部文献证据。必要的语义 API 接收 IR 中的具体引用语境和关联证据，返回带依据的分析结果，不绕过 IR 让模型直接通读 PDF 后给整篇结论。

### 快速扩展规则的机制

规则编译器接受一条或一批自然语言规则和规范依据，自动生成相应检查 pass 与变异构造能力，复用共享 IR、分析接口、执行器和反馈循环。每条规则可以有独立生成程序，但不应要求人工为每条规则开发新检测器。新规则确实需要缺失表示时，由系统提出共享模型扩展及配套分析实现，验证后供后续规则复用；生成和修订的核心流程不能依赖 R31／R32／R33 特例。

30／300 条规则是架构的扩展目标；本轮仍只用三条规则验证通用编译与自迭代，报告新增规则的人工专用代码和干预次数，不提前声称已完成大规模扩展实验。

### 离线编译与反馈流程

```mermaid
flowchart TD
    PDF[论文 PDF] --> REP[共享模型解析：结构树、符号绑定及语义关系]
    RULE[自然语言规则＋标准条款] --> MUT[大模型生成变异方案与合规对照]
    REP --> MUT
    MUT --> VERIFY[通用引擎应用变异；另行复核有效性及标签]
    VERIFY --> SPLIT[按母本分组；冻结内容、标签及三个集合]
    RULE --> GEN[大模型将规则编译成检查 pass 与必要的模型扩展]
    REP --> GEN
    GEN --> STATE[候选版本：共享模型、分析能力、检测程序]
    STATE --> RUN[按候选重建受影响 IR；执行检测]
    SPLIT -->|反馈集与验证集| RUN
    RUN --> FB[仅反馈集的误报、漏报及失败证据]
    RUN --> VAL[验证集评分；由评测器保管]
    FB --> STOP{反馈集收敛或达到轮数、预算上限？}
    STOP -->|否| REFINE[大模型归因并修订检测程序或 Paper Model]
    REFINE --> STATE
    STOP -->|是| SELECT[按验证评分选择已执行候选]
    VAL --> SELECT
    SELECT --> TEST[冻结候选后进行独立留出测试]
    SPLIT -. 留出内容不参与生成、修订或选择 .-> TEST
    TEST --> REPORT[迭代前后成绩、每轮变化、成本与未解决问题]
```

程序及模型状态记为 S_t = (M_t, A_t, D_t)，分别表示论文模型、解析分析能力和检测程序。每轮用已知预期的反馈数据计算失败集合 F_t，再执行 S_(t+1) = Refine(rule, S_t, F_t, history)。模型和分析变化后，重新从原始来源或合法变异内容构建受影响表示；保持预期与证据不变。

样本生成、验证与划分在主实验开始前完成并冻结。修订模型时只从同一原始来源或合法变异内容重建表示，不重新生成、标注或划分 benchmark。数据构造和验证所用对话历史不得传入检测程序生成或修订，避免暴露留出案例。

生成与修订代码均由配置好的华为云 API 完成。模型权重不更新；迭代对象是程序、模型定义和解析分析能力。普通编译、执行、变异应用与统计由程序完成。

### 程序生成路线

采用直接生成读取 IR 的 Python 检测程序和可审计模型补丁的路线，统一通过受限执行接口运行。结构化规则解释可作为可读的生成计划保留，但不再要求所有检测逻辑只能拼现有 Rule IR 的有限算子。检测程序只能通过声明的共享接口读取分析结果、查询证据和请求必要的语义判断，输出统一状态、位置、依据与证据。

另一条可行路线是保留 Rule IR，并自动扩展算子和分析能力；它具有较强的类型约束，但本次需要额外建设自动扩算子机制。当前选择直接程序合成，集中验证“反馈能否改进程序及表示”。

通用执行器、反馈器、修订器不得根据 31/32/33 选择手写检测实现。三条规则的差异放在自然语言任务、标准资料和数据中。原有 PDF 来源映射、引用绑定、公开证据网关、费用控制与隔离执行可作为共享基础复用。

旧 Rule IR 编译与表达式解释路径保留用于兼容、回归和历史复现，不作为新主路径的前置限制。新规则包明确标记格式与接口版本，加载器及执行器需支持直接程序合成；不能继续要求 Python 源码必须等于旧表达式生成器的输出。主实验的一次生成基线也是新路径第 0 轮，不把旧人工修好的规则包充当基线。

### 自动变异与样本验证

给定自然语言规则、规范、初始 IR 接口与来源内容，由大模型自动生成变异构造程序或方案，同时覆盖违规变异及合规、等价对照。构造程序输出带前置条件的修改提案，由通用变异引擎应用，保留来源、变异位置和派生记录，清除受影响的旧分析。现有手写 format_recipe 可用于冒烟和历史复现，新主实验不依赖开发者逐规则编写变异配方。

变异生成器给出的预期只是待验证声明。结构检查证明 IR 合法，不能证明规则标签正确。另行验证原样本是否合规、变异是否造成目标违规、证据是否支持标签，再把标签与变异目标密封在评测侧。检测器不能读取这些信息。无效、证据不足或复核冲突的候选保留原因并排除有效样本计数；不得凭模型自称有效凑足 100 个。

## 4 反馈与自迭代的语义

每条反馈至少包含：原规则与标准依据、目标局部原始/变异内容、实际输出、独立预期、对应来源证据、失败类别、当前代码/模型版本。修订器可以读取反馈集的预期和案例；正常检测程序不得读取任何预期、变异目标或测试答案。

- 漏报：有确定违规预期，但没有检出目标违规。UNKNOWN 和 ERROR 不能被记成检出。
- 误报：有确定合规预期，程序却报告违规。
- 未知：单列证据/表示不足，不能直接说成已证明的误报或漏报，也不能当作通过。
- 执行错误：单列编译、运行或接口失败。

修订器先区分规则程序问题、表示缺失、抽取/绑定错误、事实证据不足。前面三类允许生成有针对性的补丁；证据不足可以通过已有来源补查，不能靠修改事实或标签消除失败。

模型补丁以带版本的声明和生成代码保存，经检查后加载，不能直接任意改写生产仓库。表示重建必须保留原文来源，禁止通过改动论文原文、预期标签或评价脚本来提高成绩。内部程序变了却没有重新执行的版本不得记为已验证版本。

新增表示必须配套可执行的解析或分析能力、来源证据与契约检查，只添加节点名称不算能力完成。某条规则提出的共享模型变更必须回归其他已生成规则，保存兼容版本，不能把不同模型版本的程序随意拼成发布包。没有实际触发模型扩展时，应如实报告，不能预先声称证明了表示协同迭代的收益。

每轮重新运行反馈集及既有回归对照。验证集用于按预先确定的指标选择候选，不向修订器提供逐例答案或失败内容；最终测试集不参与任何修订或选择。达到轮数或预算上限时输出已验证的最佳候选与完整失败记录，不强行制造收敛。

提前收敛指反馈集没有已验证误报或漏报，且没有 UNKNOWN／ERROR；它不代表未知论文上不存在错误。若没有任何通过执行检查的候选，则报告失败，不把未执行代码作为最终程序。

## 5 实验设计

### 数据与计数

每条规则先冻结 100 个经过验证的违规 mutant，合计 300 个；另为每条准备至少 30 个合规/等价对照。用户已确认 100 个是总样本量，按母本分组，目标为约 60 个反馈、20 个验证、20 个独立测试；分组导致的数量偏差须完整披露，不通过跨集合复用母本来凑比例。同一母本及其全部变体不得跨集合，避免对同一原文的记忆混入留出测试。

三条规则共用母本分组清单，避免共享模型通过另一条规则的反馈接触留出母本。合规对照按相同分组原则划分；构造语境按其构造母本分组。若预算内无法完成样本目标，必须报告未完成数量，不能擅自改变分母或补入未验证样本。

100 是每条规则的总 mutant 数，涵盖这三个集合，不意味着 100 个全部都是最终留出测试；最终结果必须标明各自分母。样本数不足时先继续构造不同位置和不同变异类型的有效变体，不能复制同一个内容、将合规对照、未验证负例或执行错误充数。

R31 的违规预期来自适用标准条款与明确的格式变异；R33 的预期来自具体引用用途及可定位的被引内容证据，不能仅以主题差异、摘要没提到或模型自评作为确定负例。独立提示与同一模型族不等于独立人工金标准，应记录模型参与验证的范围。

用户已选择 R33 全自动标注并另行复核，涵盖反馈、验证、独立测试及合规对照。标注与复核采用分开的模型调用和上下文，复核者读取规则与来源证据，不读取检测器预测作为答案；精确检查引用语境及被引文献中的证据引句。冲突、证据不足和无法定位的候选不进入有效标签集。保留模型及提示版本、原始答复、证据定位、复核结论和排除原因。最终论文使用“模型辅助标签”，披露共同模型偏差，不使用“人工金标准”或把复核通过等同于标签绝对正确。

R33 优先从真实论文原有的引用语境派生 mutant。如果可靠负例不足，系统可以根据真实文献内容自动构造有明确支持证据的合规引用句，再替换引用或改变语境以形成违规 mutant。每个样本记录语境来源为真实原句或系统构造、构造记录、原文证据及验证结果。真实语境和构造语境分别报告样本数、检出率与误报率；构造语境不得标注为原 PDF 中实际存在的句子，也不提供虚假的 PDF 定位。同一构造母本及其变体遵守相同的集合隔离要求。

### R32 的两个实验环境

受控环境提供完整、固定的文献全集，存在性结论限定于这一明确范围。100 个违规 mutant 在此环境构造并验证；正常检测输入提供合法的库访问接口，而非答案或 mutant 标记。至少覆盖题名/作者形式变化、标识符与作品身份联合核对等情形，不把匹配器只记住编号当成完整语义核验。

开放环境继续核验真实论文中的外部作品，记录身份确认、明确冲突、UNKNOWN、检索覆盖与成本。公开检索未命中不能证明现实世界不存在；开放实验不得与受控负例合并计算“现实世界不存在检测准确率”。

### 比较与结果

主对照为同一新框架的初始一次生成程序与完整反馈闭环；第 0 轮即为 baseline，不用人工修好的旧规则包替代。关键消融为固定 Paper Model、仅迭代检测程序，与允许必要模型/分析修订的完整闭环。各条件保持相同数据划分、证据环境与最多 5 轮的上限，单独报告调用量，不能声称一次生成与多轮迭代的计算预算相同。

最终候选按验证集选择；所有轮次结束后才运行留出测试。可以在结束后统一重放已保存的各轮版本绘制测试曲线，但不得据此再选择或修订版本。

输出按规则和变异类型列出：违规检出率、合规误报率、UNKNOWN/ERROR、严格正确率、定位正确率、有效样本与母本数；同时给出版本、反例、补丁、每轮成本与耗时。用于选择的严格平衡正确率对违规和合规分别计算正确比例，UNKNOWN/ERROR 均不给正确分，防止靠弃答提高选择分数。

数据构造、标注复核、解析分析、程序生成修订、辅助语义判断、对照及消融产生的全部华为云请求都进入同一 200 元累计账本，包含已有支出。辅助请求不隐藏在程序迭代轮数中，单独报告用途与成本；任何阶段在请求前预留费用，余额不足即停止并保留可续跑状态，不自行增加额度或重置账本。

只有三条规则的实验不能证明已经在 30 或 300 条规则上验证 scale；本轮证明范围是统一框架在三类引用规则上的自动生成与反馈迭代，并报告新增任务所需的人工专用实现是否为零。

## 6 与已有研究的关系

Self-Refine 已研究“生成—反馈—修订”，Reflexion 已研究基于任务反馈的语言反思，CEGIS 提供候选生成与反例验证的经典思路。因此不能将“接一个大模型反馈循环”本身直接宣称为新颖贡献。

本项目要验证的具体研究主张是：基于论文结构树、符号与引用关系的统一表示上的规则程序合成，来源约束的 IR 变异反例反馈，以及检测程序与论文模型的协同修订。它们是否有效由主实验和消融支持，不预先宣称效果或发表保证；本框架的经验验证也不等同于形式化正确性证明。

## 8 上线后持续迭代与冻结开关（默认不冻结）

首次生产启用仍等待结果及上线要求。上线后提供可配置、持久化并在页面及 API 中明确呈现的布尔开关 `freeze`，默认 `false`。每次用户输入 PDF 都使用当前已验证的共享版本创建 Paper IR、获取证据并检测；不冻结时同时进入自动评估流程。通过证据补查、另行复核、有效局部变异和合规对照，或经核验的用户纠错，识别有依据的误报、漏报及表示不足，再调用 API 修订模型、解析分析能力或检测程序。每次输入参与评估不意味着没有问题也必须修改代码。

`freeze=true` 时锁定当前兼容版本，只进行 PDF→IR→检测→报告，以及固定策略下的证据获取和必要语义判断；不发起模型或检测程序修订，不修改共享版本，不晋级候选。恢复 `freeze=false` 后，后续输入可继续自动迭代。开关只控制系统自迭代，不影响正常检测，也不解除正式实验数据、标签和测试候选的冻结约束。

```mermaid
flowchart TD
    PDF[每次用户输入 PDF] --> PARSE[当前已验证的共享模型与解析分析程序]
    PARSE --> IR[本篇论文的 Paper IR]
    IR --> DETECT[当前检测程序与必要的语义 API]
    DETECT --> MODE{freeze 开关？}
    MODE -->|true：冻结| REPORT[返回结论、定位、证据及无法判断项]
    MODE -->|false：默认不冻结| VERIFY[补查、复核及 IR 变异验证]
    VERIFY --> NEED{存在可靠反馈或表示缺口？}
    NEED -->|无| REPORT
    NEED -->|有| REFINE[API 自动修订 Paper Model、分析能力与检测程序]
    REFINE --> CANDIDATE[候选版本重建 IR、复检及受影响规则回归]
    CANDIDATE --> GATE{达到自动晋级标准？}
    GATE -->|通过且仍未冻结| PROMOTE[原子启用新共享版本]
    PROMOTE --> REPORT
    PROMOTE -. 后续输入复用并继续迭代 .-> PARSE
    GATE -->|未通过且额度轮次允许| REFINE
    GATE -->|已冻结、失败或达到限额| KEEP[保留旧版，记录未解决问题]
    KEEP --> REPORT
```

在线修订与复检在候选版本中完成，不直接任意改写生产仓库。模型、解析分析能力、检测程序、提示词及判断配置组成兼容的版本包，每轮执行使用不可变快照；通过首次上线前确定的自动晋级标准后，原子切换到新共享版本，不要求人工逐次批准修订。失败或退化保留旧版，保存历史报告、候选与回滚路径，处理并发晋级冲突及不同用户数据访问隔离。

切换为冻结后停止后续修订调用，已在途调用的候选可留档，但冻结期间不得晋级；启用新版本前必须再次核对开关与父版本。每次检测使用完整快照，升级后通过新的复检记录体现，不在一次执行中混用模型与程序。控制开关的权限沿用系统现有权限规则，记录实际生效值和切换事件。

原 PDF 保持不变，所有变异与检测仍在 IR 上完成。在线反馈也必须有可核验依据；报警、公开搜索未命中或同一模型自称错误都不能直接成为可靠标签。R33 继续自动标注、另行复核并保留模型辅助标签说明。正式实验内容、标签和划分仍冻结，不能用正式独立测试答案驱动在线修订后继续声称测试独立。

离线实验每条最多 5 轮的约定保留；在线按每个任务设置明确的轮数、时延和费用限额，不把它解释成上线后一共只能更新 5 次。解析、补证据、标注复核、语义判断、代码和模型修订的全部模型费用仍进入同一 200 元累计账本，余额不足即停止收费并返回实际状态，不绕过预算。

请求记录可用模型版本、提示版本和输入及证据指纹；相同版本、相同输入及证据优先复用缓存，模型或程序变化后重建受影响分析。第三方服务可能变化，应保留快照和证据，不声称完全消除外部波动。用户随后已明确恢复按 TODO 实施；实现、实验按既定预算与首次发布边界继续，完成且验证后逐项勾选。
