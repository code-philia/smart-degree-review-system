# 第 31—33 条：模型、规则编译与全量上线设计

状态：v0.2 设计方案；业务范围来自用户逐项确认。以下模块与门槛尚未实现。本文件与主设计共同作为审阅稿。

## 1. 本阶段的最小完整架构

| 模块 | 输入 | 输出与责任 |
| --- | --- | --- |
| PDF Frontend | 原 PDF、既有 MinerU/OCR 观测 | Layout IR、结构 AST、质量与来源范围；不执行课题规则 |
| Model Registry | 类型、字段、关系、能力、迁移版本 | 可装载契约与编译期类型信息；统一引用和字段表达 |
| Analysis Planner | 启用规则的能力依赖、当前快照 | 构建引用组、条目字段、绑定、引用用途及共享证据的依赖 DAG |
| Evidence Gateway | 外部资源身份、查询计划、证据请求 | 元数据/摘要/全文/查询失败事实，带来源、时间、覆盖和哈希 |
| Rule Compiler | 自然语言、标准、模型契约 | 经类型与证据校验的 RuleSpec、Rule IR、生成检测代码 |
| Capability Builder | 编译发现的能力缺口 | schema/迁移/通用分析代码/提示词候选及测试；自动验证后注册 |
| Check Runtime | 当前 IR、匹配分析、规则包 | 按对象的结果、位置、证据和整篇状态；不读 oracle |
| Mutation / Evaluation | 目标约束、前置条件、样例策略 | IR 变体、隔离的预期、独立测试与覆盖指标 |
| Repair / Release | 可验证反例、旧稳定包 | 有界候选、回归、影子评估、自动晋级和回滚 |
| Web Adapter / Batch | 网站任务、论文列表 | 异步进度、可定位报告、断点恢复及全量汇总 |

部署目录仍使用现有服务发布机制，开发在唯一目录 /data/projects/smart-degree-review-system。模型能力的开发候选在该项目的独立进程/临时任务目录中验证，不另建 worktree，不直接改变正在服务的规则版本。

## 2. 引用所需的具体 IR 契约

- CitationGroup 保存原始括号、范围/并列分隔、上下标等标记属性以及多个原子 CitationUse；字段与字形都能定位。
- BibliographyEntry 保存原始著录文本、条目键、文献类型候选、字段观测与字段来源；作者、题名、年份、出处、卷期页、标识符、URL 等有 observed / absent / unknown 状态。
- CitationStyle 是整篇和局部区域的体例观测，支持顺序编码和著者—年份等适用形式；自动识别冲突和局部引用误分类，不因一个异常符号切换整篇体例。
- ExternalWork 区分作品、版本和载体；IdentityResolution 保存候选身份、匹配字段、冲突字段、检索路径和证据。
- EvidenceRecord 包含 source、retrieved_at、resource_identity、content_hash、coverage_scope、content_kind、文本片段与定位、响应状态和是否测试环境。
- CitationIntent/Claim 保存引用处的具体用途和陈述范围；RelevanceAssessment 指向用到的上下文与文献片段，明确相关、明确不相关或信息不足。
- AnalysisSnapshot 保存父 IR 哈希、构建器/能力版本、外部证据版本和依赖哈希。IR 一旦变异，相关绑定、字段、身份及语义判断失效。

IR 装载不要求引用正确；字段缺失和身份未知必须能够保留。读取外部文献属于证据构建 pass；检测规则只读取已经纳入版本化分析的证据。规则可请求补充证据，运行时调度后重试，不能绕过 IR 对 PDF 做独立词语匹配。

## 3. R31：正文标注与文末著录格式

适用依据使用所供 GB/T 7714—2025 与 GB/T 7713.1—2025 的已核验条款。本阶段采用所供版本作研究检查，不据此评价历史归档时是否满足当年的毕业要求。

R31 是一个带子检查编号的规则包：正文引用体例和标记语法、整篇体例一致性、相应顺序/消歧格式；文末按资源类型适用的字段、字段顺序、著录符号及标点。每项必须附条款、规范强度、类型和例外，不能给所有资源套同一模板。

大模型可用于条目分割、字段/文献类型判别及规则解释；已确定的字段约束、语法和顺序由生成代码执行。原 PDF 确实存在的标点不能在规范化时丢掉后被报告缺失；OCR 疑点先自动重读对应区域。

条目缺 DOI 不一律报错；URL 已携带永久标识符时按条款处理。机构作者、缺个别元数据的合法著录方式、译名、不同载体和可选字段按对应条件处理。

R31 检查形式；正文找不到本地条目仍归 R22 的逻辑，新系统可记录绑定未决以便阻止后续错误判断，但本阶段不另行上线 R22 替代实现。

预期诊断：定位正文标记或具体文末字段，说明违反哪一条适用格式要求、原始内容和期望形式。大模型给出的格式建议不能自动改写原论文。

## 4. R32：外部文献真实性与身份核验

查询先用标识符与其解析结果，再用题名、作者、年份、出处、版本别名等组合匹配；必要时查询出版者/仓储的原始记录及独立来源。来源适配器需要明确覆盖范围，尤其中文文献和学位论文，不能把未收录等同不存在。

| 证据情形 | 检测结论 |
| --- | --- |
| 可信原始记录与核心身份相容；标识符/版本差异有合理解释 | PASS，记录核验的具体身份 |
| DOI 指错资源，但题名等证据能找到真实目标作品 | 不据此报“文献不存在”；标识符/著录身份问题单独记录，避免混同 R26 |
| 对所声称、可穷尽核对的具体资源范围有明确排除证据，替代题名/版本/录入错误路径也无法解释 | 只在证据义务满足时报告 VIOLATION，措辞限定为“所列资源身份不成立/疑似不存在”，不推断作者故意伪造 |
| 多次未命中、404、摘要未提供、来源覆盖有限或接口故障 | 自动扩大查询并重试；仍不足为 UNKNOWN 或 ERROR，不作为不存在证据 |

“全网不存在”通常不能由若干次搜索证明。高精度目标下，真实任务中的否定结论应少而证据充分；不能为了降低 UNKNOWN 率把检索失败改名为不存在。

测试中的封闭合成目录可以给出确定不存在的 oracle；该目录只能证明测试范围内的预期逻辑，不能作为真实互联网的完整性假设。真实肯定样本可用成功核验的资源作为自动可验证依据。

## 5. R33：按本次引用用途判断相关性

每个引用点先绑定条目与外部作品，提取所在句、必要前后文、所属段落/章节角色，以及背景、方法、数据、对照、批评等用途。比较的是该用途与外部内容，主题相似度只辅助。

可用全文时选择有关片段；摘要足够支持判断时允许摘要。若用途需要具体实验细节而摘要无对应信息，则补取全文/相关片段，不把摘要未提及直接作为反证。仅有题名一般不能做最终否定判断。

语义服务输出结构化关系、证据片段 ID、用途解释、反向解释和不确定原因。判断“使用一种统计方法”不等于要求被引文献也研究医学；批评某结论不等于引用文献必须赞同本论文。

有明确内容证据且替代合理用途被排除，才报告“疑似不相关”；自动核验后仍信息不足为 UNKNOWN。VIOLATION 表示触发课题的相关性规则，诊断保留“疑似”和证据范围，不升级为学术不端认定。

引用组可能共同支撑一个论述，先确定各成员承担的用途；不能强制每篇文献支持整组陈述的全部内容。无可靠外部身份时不对猜测的文献做 R33 判断。

## 6. 自动编译的完整产物和接口

自然语言规则保持原文，编译器加载标准片段与模型契约，生成 RuleSpec。RuleSpec 指定选取对象、适用条件、请求证据、判定表达式、诊断锚点及无法判定路径。类型与能力检查将它变成 Rule IR；确定性后端生成只调用受控接口的检查模块。

建议接口：build_paper(source, model_version)、compile_rule(rule_text, standards, model_contract)、ensure_capabilities(requests)、enrich(ir, capability_plan)、check(ir, analysis, rule_package)、mutate(ir, recipe)、evaluate(package, sealed_cases)、propose_repair(counterexample)、promote(candidate, gate_report)。这些是待实现的契约名称，不是已经存在的库 API。

R31 复用 style/field validation；R32 复用 external identity evidence；R33 复用 context/intent/evidence semantic judgment。不存在的能力走自动生成—测试—注册流程。规则解释器和候选生成器需要模型 API；编译器后端、类型检查器、缓存和调度可以确定性运行。

参考文献文本和外部检索内容均是数据，不能包含可执行的代理指令。候选代码生成环境与检测生产运行环境分开；只通过约束接口取得所需证据。

## 7. 变异、自动真值与修复

| 测试类别 | 变化位置 | 自动依据 |
| --- | --- | --- |
| R31 标记损坏、必需字段删除 | CitationGroup / BibliographyEntry 原始内容 | 已确定体例与字段前置条件、可计算的语法约束 |
| R32 身份替换 | BibliographyEntry 原始身份内容 | 有覆盖声明的受控测试目录；真实存在正例的来源记录 |
| R33 无关资源替换 | 条目的资源身份或引用位置的内容 | 可控、明确相反的上下文/文献内容；独立验证器；不直接改 relevance 结果 |
| 等价变异 | 换行、可解释别名、同义表达 | 对相关约束的结果不变 |
| 来源不可用、只剩题名等 | 证据适配器测试环境 | 验证 UNKNOWN/ERROR，不伪装为论文变异 |

样例生成器、变异器与检查器不能共享 expected 标签；检查输入只含当前有效 IR 和正常接口取得的证据。候选修复器不能修改 oracle 或评价器来通过测试。

自动发现失败并不要求人工标注：可控样例错判、等价变化导致无依据结论翻转、引用绑定与原始片段不相容等形成反例。真实语义分歧只触发进一步核验，未得到独立支持前不贴“已证实误报/漏报”标签。

修复示例：跨行题名被截短 → R32 查不到 → 独立来源/第二种提取与页面片段支持完整题名 → 定位到通用条目构建器 → 自动生成续行处理候选 → 正反/跨页/新条目边界回归 → 重建 IR → 自动晋级。绝不能将未知文献的标题替换成搜到的任意相似作品。

## 8. 验收口径

本节是工程验收设计，不是已测成绩。

### 上线前必须真实运行的 IR 变异评测

用户明确要求新方法上线前进行变异检测。评测在隔离环境执行，发布只有在变异评测、自动修复回归和原始全量运行完成后才能发生。

1. 从 479 篇真实论文构建 IR。自动选择前置条件有独立证据的引用位置；原始整篇不预设通过。真实母本与可控合成母本分别建清单。
2. 在 IR 原始内容/结构上制造 R31 标记或字段违规、R32 资源身份变体、R33 与用途无关的引用，并生成等价和有效非违规对照；重建受影响分析，保留完整变异事务。
3. 独立验证变体是否确实满足预期条件。R32 的封闭目录否定只作对应范围的受控评测；真实检索未命中不能自动生成“确定不存在”的 gold label。R33 无充分证据的替换不计为已证实违规。
4. 使用与拟上线版本完全相同的编译器、模型契约、规则包与分析能力版本运行原始/变体检测，冻结输入及证据快照，禁止读取 oracle。
5. 每条规则分别统计有效违规变体的检出/漏检、有效非违规局部的误报、UNKNOWN/ERROR、正确定位以及无效变异数量；区分真实母本、合成母本和环境故障。原论文中已有报警不能冒充命中了新变异，未决样本不能被算成通过。
6. 自动修复候选后重建分析并执行相关变异、冻结回归、等价对照及独立保留测试；最终发布包必须有通过记录。不能通过修改预期、删除失败样本或降低覆盖来通过门槛。
7. 再对原始 479 篇完成三个规则的全量运行，形成 1437 个终态记录及对象覆盖报告；通过网站集成、旧规则回归与健康检查后发布。发布后核对运行版本与验收包哈希一致。

### 具体交付门槛

1. 编译：31、32、33 均从原始自然语言输入产生可追溯 RuleSpec/Rule IR/代码；另用未参与候选生成的规则变体验证组合能力。缺失能力的自动扩展至少有一个受控演示，不以手工补代码冒充。
2. 受控 oracle：设计建议每条至少 100 个违规和 100 个非违规样例，另有至少 20 个证据不足/异常样例；这是工程初始门槛，不是用户给定或已经完成的数量。跨语句与引用形式覆盖，去除重复模板计数膨胀。真实母本与合成母本的有效数量分别报告；具体样例自动生成后验证前置条件。冻结的有效 oracle 用例必须符合预期，候选无新增误报；语义合成结果只代表该测试范围。
3. 解析：源片段对应、字符/字段来源、引用绑定、跨行跨页、OCR 差异及再解析一致性有机器可检查证据；两个解析器相同不自动等于真实正确。
4. 自动修复：从可验证失败到候选、重建、回归、自动晋级/拒绝、回滚均能演示；没有人工标注/批准步骤。
5. 全量：479 个源 PDF 清单冻结；每篇每条都有终态，合计 1437 个运行记录。报告每条对象总数、已完成/违规/未知/错误数及覆盖，不能仅展示“任务完成”。
6. 全量不预设零报警；不把原始论文当作负例，不把未标注的真实全量结果称为 precision/recall。受控集与真实集分开报告。
7. UNKNOWN：先分原因自动补救，记录补救前后变化；不吞掉难例，不缩小适用范围，不将 UNKNOWN 当 PASS。绝对比例由真实基线测量；用户未指定可承诺的百分比。
8. 网站：规则目录、单篇与归档任务、PDF 定位、证据展示、取消/重试/断点恢复、旧 10 条回归、服务 active/enabled 与公网页面检查通过；源 PDF 和业务数据保留。

现有归档清单含 350 development 与 129 holdout 划分，可作为初始分组设计；旧流程可能已看过整批数据，不能把这 129 篇宣称为此前从未使用的独立盲测集。新合成测试使用隔离种子与样式，真实集只作运行质量和覆盖审计。

## 9. 运行与配置边界

本阶段 API 配置推迟，先完成设计和接口。实际联调需要模型供应商、模型 ID、地址、服务器私有密钥，以及可用的文献证据来源。来源适配器要覆盖本批论文需要的中文/英文文献；具体服务在接入时核验其接口、许可和可用性。

运行参数必须有重试、候选轮数、单任务和整批预算、并发/限流上限；未配置可消费的真实服务时不自动启动 479 篇收费任务。该配置阶段不会重新询问是否需要实现已经确认的功能。

结果使用新版本报告与新文件，不修改 30条规则_变异检测结果.csv。文档和示例通过机械检查也不等于上述验收已经完成。
