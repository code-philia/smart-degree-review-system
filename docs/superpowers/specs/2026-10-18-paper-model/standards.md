# 规范依据、核验范围与模型映射

本表依据用户提供的本地版本。页码同时给出“PDF 第几页”和纸面页码，均从 1 起；它们不是模型中从 0 起的 `page_index`。没有完成每份标准的逐条数字化，也没有把所有项目规则宣称为国标原文。

## 核验范围

17 个文件已登记页数和 SHA256，见 `sources.json`。重点视觉核对了 S15（论文编写）PDF 第 7、9–13、15 页，S13（参考文献）第 9、14、29–31 页，S03（表格）第 5–7 页，S04（插图）第 5–7 页，S09（量与单位）第 3–4 页；提取阅读了 S11（摘要）全文及 S01（术语）。其余主要作为扩展标准目录，不能视为已逐条编译。

源文件名不总是标准的正式标题。S15 封面为 **GB/T 7713.1—2025《信息与文献 编写规则 第 1 部分：学位论文》**；原文件名仍保留。S09 文件名为 GB/T 3101，但所供扫描页印为 GB 3101—93；模型保存原始版本信息，未自行判断其现行效力或替换为别的版本。

## 规范不等于一个布尔开关

`NormativeBasis` 保存 `source_id / clause / pdf_page / printed_page / modality / applicability / interpretation_version / verification_status`。规范强度至少区分 must、should、may、conditional，以及条款中的例外。项目判定策略另存 `policy_strength`。

用户已确认一套优先关系：适用国标有明确规定时，以国标为准，自动校正与其冲突的输入规则；国标未覆盖但老师明确要求的问题仍检测并影响最终结果。每个结果区分 `national_standard` 与 `project_requirement`，保留原始规则、校正内容和依据。

当前激活 profile 为 `archive479-citations-v1`，只启用 31—33；其余规则保留建模映射。不得把“宜”自动升为国标强制要求，也不得把课题语义判据标成国标原文。

**例一，表题强度：** S15 §5.3.3 使用“宜有表题”，而其引用的 S03 §4.2.2.1 使用“应有表题”。模型保留两条要求和 `normative_conflict`，供 profile 固定解释；不能默默选一条后宣称整个国标只有一种强度。这一冲突需在后续迁移规则 14 时按标准适用关系自动解析；本阶段不改变现有 14 的运行。

**例二，身份信息：** S15 的正式题名页要求包含责任者信息；项目规则 30 针对匿名评审稿。匿名稿必须使用独立适用条件及学校/项目匿名要求，不能把“国标禁止作者姓名”写入模型。

**例三，图使用：** 图应随文出现、自明，与项目“出现未被引用的图”之间需要明确何为正文使用。显式编号、图的描述性提及、图内部编号、图表清单不是同一种证据。

## 尚未能作为完整可执行依据的资料

- S12 GB/T 7408.1—2023 仅 3 页：封面、空页和目录，缺少规范正文。可建立日期类型，不据此声称日期格式检查已完整依据该标准。
- S01 术语副本有 `CY/T ××××` 等页眉占位信息；条款可用于本设计讨论，但来源质量记录为 `copy_requires_authority_check`。
- S06、S08、S10、S14、S16、S17、S05 以及 S07 等已登记，未逐条核验/编译。扩展到标点、拼音、数字、索引、关键词和编号细则时，应补充分条款映射。
- 规则 26–27、30、32–33 的特定判据不是已经从这些标准中找到的逐字强制条款；按项目扩展要求登记。外部存在性、相关性还需要外部证据与评价协议。

这类缺口不阻止本轮设计 IR，但会阻止未来对相关子规则给出“国标全文已检查”的结论。
