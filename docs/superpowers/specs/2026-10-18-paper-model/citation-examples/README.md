# 31—33 完整设计示例

本目录是可机械核对的设计数据，**不是 API 实测，也不是已实现的编译器**。文献及其目录完全合成。原有全文 67 节点示例见 [通用结构示例](../examples/README.md)；这里集中展示本阶段的引用链。

## 1. 阅读顺序

1. source-paper.txt：医学测量论文引用统计重采样方法。跨学科，但用途合理。
2. paper.ir.json：20 个结构节点，包括题名、摘要、方法/结果/结论、引用和参考文献；字符范围指向实际存在的文本文件。
3. paper.analysis.design.json：基线的引用绑定、方法用途与外部作品关系，明确标为设计数据。
4. rulespecs.design.json → rule-ir.design.json → generated-checks.py.txt：自然语言规则的结构化形状、编译计划与生成代码形状；尚未调用模型生成，代码中的运行时接口也尚未实现。
5. capability-request.design.json：类型/能力不足时自动请求扩展，而非等待人补代码。
6. snapshots、mutations.json、oracle.expected.json：五个独立 IR 变体与十种运行场景；检测器不得读取 mutations/oracle。
7. diagnostic.design.json：明确无关引用的预期报告样式。

R31 示例只展开“数字标记配对”和“期刊条目题名存在”两个子检查，其 PASS 不代表整个 GB/T 7714 已完整覆盖。生产规则包还需编译全部适用子约束。

## 2. 同一模型下三个问题的区别

    当前引用标记及著录文字 ─ R31：形式符合适用规范吗？
    BibliographyEntry → ExternalWork ─ R32：所列资源身份存在吗？
    引用用途＋ExternalWork 内容 ─ R33：该资源与这次使用相关吗？

基线的论文主题是医学，外部文献主题是统计，但方法用途成立。将条目替换为目录里真实存在的诗歌文章，只应触发 R33 的不相关，不能报 R32 不存在。将条目改成测试目录中没有的身份，在封闭目录内有否定依据；在开放检索范围内仍只能 UNKNOWN。

## 3. 检测输入和评测答案隔离

论文输入只包含选定的当前 IR；外部适配器读取指定证据环境并产生正常证据快照。变异名、期望规则、预期结果和父版本诊断不进入检查输入。快照文件名及操作 ID 使用不含目标规则号的哈希。

五个 IR 变体只改变源内容，不直接改变绑定或语义结论。各变体必须重新抽取分析；基线 analysis 由父 IR 哈希约束，不能当变体的分析结果。变异节点保留祖先来源但标 synthetic。

环境反事实与服务故障用例测试证据边界，不宣称是在 PDF 或 Paper IR 上做了论文变异。PDF 坐标没有在文本教学样例中捏造；网站版本须由实际 PDF 前端提供。

## 4. 外部不存在的边界

evidence-environment.json 是完整枚举的封闭测试目录，明确禁止生产使用；它为测试提供确定 oracle。open-evidence-environment.json 明确不是穷尽目录。相同的未命中文献在两者中有不同预期，避免训练出“检索失败＝伪造”。

生产系统不得用该测试假设代替互联网覆盖；真实 R32 结论需要正文说明的资源身份与负向证据契约。标题/DOI 排错或版本差异有其他解释时要保留，不推断作者故意编造。

## 5. 从设计样例到自动编译与检测

生产运行时由大模型解释自然语言规则、生成并校验新规则所需的缺失能力；确定性编译器生成受控检测模块。测试生成器根据独立构造约束创建样例，验证器确认前置条件、隔离预期并执行回归。按 v0.4 范围，本阶段不实现检测系统自修复或论文修复建议。当前文件用于说明契约，不能替代自动编译、检测与测试过程的实现。

本目录的验证脚本只核对树、来源区间、哈希、引用、变异编辑和预期分支自洽；不验证真实语义准确率。
