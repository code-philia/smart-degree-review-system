# 六条 PDF 规则检测器设计

## 目标

在现有基础规则检测增加规则 11、13、14、15、16、29；规则 6 继续暂停，已有四规则不改。每条规则列出全部发现、原 PDF 页码及 bbox；证据不足时显示无法判定。新检测器按抽取、索引、逐规则判断和服务适配拆分小模块。

## 解析架构

规则 11、15、16、29 以 PyMuPDF 提取的全文文本和几何信息为主。规则 13、14 需要识别真实图表对象，开发和上线阶段均使用 MinerU 精准解析 API 获取版面 JSON。远程适配器输出统一的图表对象结构；将来服务器资源允许时再替换为本地 MinerU，规则判断不变。无需其他大模型 API。

私有论文不提供公开 URL。服务端调用 MinerU 的批量上传接口申请临时上传地址，PUT 本地 PDF，轮询结果并下载结构化 JSON。API 单文件上限 200 页、200 MB；超限论文按页拆分，结果统一映射回母 PDF 页码和 bbox。片段失败时，相应规则显示无法判定。临时片段和解析原始结果及时清理，敏感地址及 Token 不写日志或报告。

选中规则 13 或 14 后，后端直接调用 MinerU API，不要求用户额外确认，也不增加前端弹窗或复选框；只选其他规则时不调用 MinerU。Token 从后端环境变量 MINERU_API_TOKEN 读取，未配置时云解析规则不可用。MinerU 异步任务使用持久化状态、有限并发、轮询超时和明确错误，不让整篇论文堵住原有同步五分钟调用。

## 六条规则

共享索引识别正文和附录中的图号、表号、图题、表题、图表引用及附录标题，支持常见中文编号、章节小数点或连字符、附录字母编号；排除图表目录及标题自身的自引用。

- 11：图引用在全文没有对应对象或图题，高亮引用。
- 13：确认存在图对象，邻近及跨页合理区域无图题，高亮图对象。
- 14：确认存在表对象，邻近及跨页合理区域无表题；续表单独处理，高亮表对象。
- 15：图在全文非标题位置没有有效引用，高亮图题或图对象。
- 16：表在全文非标题位置没有有效引用，高亮表题或表对象。
- 29：引用本论文附录而全文没有对应附录标题，高亮引用。

把公式编号、参考文献、表格数字与真实引用区分开。对象抽取、编号或坐标不可靠时显示无法判定，不用缺失证据直接推断违规。同篇多处违规逐处列出。

## 项目接入与验证

Python 新建模块化检测包，不继续扩充 backend/scripts/five_rule_detector.py。Node 负责鉴权、Token、任务状态和既有报告格式；前端沿用规则卡、历史报告和 bbox 高亮，不设置 MinerU 用户确认步骤。

单元测试用 MinerU 假响应覆盖编号变体、长论文分页、页码映射、跨页图题、续表、重复编号、全文引用、缺失目标、Token 缺失和 API 失败；不需要真实密钥。联调用少量开发测试论文核对 MinerU JSON 和高亮位置。保留独立测试论文作最终泛化评估，不以检测结果筛样。

线上服务是 smart-degree-review.service，工作目录 /opt/smart-degree-review/current/backend。首次上线六规则时继续使用 MinerU API。部署时用 systemd EnvironmentFile 从 /etc/smart-degree-review/mineru.env 注入 MINERU_API_TOKEN，权限只给管理员读取，密钥不进 Git 或前端。上线前检查服务器能访问 MinerU 接口和上传地址，上线后以开发测试 PDF 做端到端测试。
