## 已观察的问题

`posthoc-full-feedback-r31-002` 在同一有效 API 种子上执行五轮、78 个反馈和 26 个验证样本。各轮两集严格平衡正确率均为 0；r2 后仍没有 BibliographyEntry 正向 PASS 路径，r3/r4 实际代码逐字不变。原选择器选回种子，仍有 78 个反馈错误。降低误报同时损失违规报警不算整体改善。此为失败的事后诊断，不覆盖旧正式结果。

独立通用模型诊断实际使用 249827 输入、4751 输出 token，费用 0.537662 元；存在代码和反馈轮次误读，未直接作为修复输入。默认代表例数为 12 时，r4 真实完整输入为 803657 UTF-8 字节；只变为 4 例且固定其他字段为 343150 字节，减少 57.30%。这证明输入字节减少，不证明质量或实际 token 同比例改善。

仅反馈集原始条目的独立模型辅助复核另发现两条网页条目缺必备引用日期，共影响三个原始被误标合规的违规配对。原冻结数据和成绩保留，三个配对须在新数据版本补足；不能把原始已违规当新增变异检出，不能强制 UNKNOWN 为 PASS。

## 通用修改

- 生成指令要求为有充分证据的适用义务实现 PASS 路径；UNKNOWN 必须指明具体适用义务和缺口，局部与全文范围分开，真正未知仍未知。
- 默认代表例数从 12 减为 4；显式 limit 可覆盖。全部已准入反馈的失败/状态/check 汇总、轮换、多样性和优先编译失败不变，入选样本事实与来源完整保留。原每侧最多 20 条诊断的上游限制仍在。
- 标注和复核显式覆盖完整评测目标及适用子节点，不能仅验证被修改义务；不把目标外或全文义务当成局部目标结论。
- 线上首次检测保留准备后的 IR/分析及各规则真实基线。仅宿主确定来自生成程序执行或输出的 ProgramError 可作为无语义标签 execution_error 进入现有修订路径。标记由宿主设置，原异常类型、消息及旧 catch 兼容。
- 独立审查真实复现了旧候选对三种坏分析缓存错误晋级。现在模型、capability 版本、分析字段及类型前置错误不会被恢复。没有可信 worker 记录的非零退出、CPU/信号终止、墙钟超时与宿主不可用也不触发线上付费修规则；离线错误反馈仍保留。
- 晋级仍需独立且有来源的局部违规和合规对照、完整继承/跨规则回归、已验证输入无剩余错误以及 freeze/CAS/预算守卫。执行错误本身不会产生 PASS/VIOLATION 标签。冻结时只检测并保存真实 ERROR。

这些是人工进行的通用宿主实现修复，不是手写 R31/R32/R33 检测器，不得把宿主修复成本计为 0 人工干预，也不证明 30/300 条扩展已验证。
